# عملیات فاز ۳C.۱ تا ۳C.۴

## عملیات ۳C.۴

- پیش از اصلاح عنوان یا جایگاه، نسخه نمایش‌داده‌شده را بازبینی کنید. `VERSION_CONFLICT` را خودکار retry نکنید؛ صفحه را تازه و مقدار جدید را دوباره ارزیابی کنید.
- تغییر عنوان دوره یا کلاس در نماهای مرتبط بزرگسالان قابل‌مشاهده است. اطلاعات شخصی را در عنوان وارد نکنید.
- تغییر جایگاه فقط به مقصد خالی مجاز است. `LESSON_POSITION_CONFLICT` را با renumber یا swap ضمنی دور نزنید؛ یک جایگاه خالی انتخاب کنید.
- عنوان و متن درس را فقط با ساخت و انتشار revision اصلاح کنید. PATCH فراداده درس فقط جایگاه را می‌پذیرد.
- این فاز migration ندارد؛ پس از `npm run db:generate` نباید فایل migration یا metadata تازه‌ای ایجاد شود.

## عملیات ۳C.۳

`0004` را پس از `0003` اعمال کنید. revision را بسازید، preview escaped را بازبینی و با نسخه جاری منتشر کنید. فقط `409 VERSION_CONFLICT` نیازمند refresh و تصمیم دوباره است؛ retry خودکار مجاز نیست. revision قبلاً منتشرشده با دلیل `CONTENT_ROLLBACK` و revision تازه با `CONTENT_UPDATE` منتشر می‌شود. پس از migration فقط read-only/fix-forward مجاز است.

## پیش‌نیاز

1. migrationهای `0000` تا `0004` را دقیقاً به‌ترتیب اعمال کنید؛ هیچ migration قبلی را ویرایش نکنید.
2. مدیر باید نقش فعال `ADMIN` و permissionهای صریح LMS را داشته باشد.
3. bootstrap جدید همه permissionهای بسته را می‌دهد. اگر bootstrap پیش‌تر انجام شده، permissionهای LMS باید توسط مدیر مجاز دیگری و بدون self-escalation اعطا شوند؛ در وضعیت تک‌مدیر، تا تعریف فرایند عملیاتی امن deployment را متوقف کنید.

## ترتیب امن راه‌اندازی

1. دوره را در وضعیت `DRAFT` بسازید.
2. درس text-only را با جایگاه یکتا در حالت `DRAFT` بسازید، revision را بازبینی و صریحاً منتشر کنید.
3. پس از وجود revision منتشرشده، وضعیت درس را `PUBLISHED` و دوره را `ACTIVE` کنید.
4. کلاس را ابتدا `DRAFT` و سپس `ACTIVE` کنید.
5. مدرس فعال را assign و حساب فعال بزرگسال را enroll کنید.
6. دسترسی دانشجو را از `/learn/` و نمای بدون roster مدرس را از `/teach/` بررسی کنید.

## عملیات چرخه عمر

- پیش از هر تغییر، نسخه نمایش‌داده‌شده را بازبینی کنید. پاسخ `409 VERSION_CONFLICT` یعنی اپراتور باید صفحه را تازه و وضعیت جدید را دوباره ارزیابی کند؛ retry خودکار مجاز نیست. سایر کدهای `409` باید بر اساس کد خطای خود بررسی شوند.
- دلیل آزاد وارد نکنید. برای هر گذار از کد بسته متناظر استفاده کنید: `CONTENT_READY`، `TEMPORARY_PAUSE`، `PROGRAM_CLOSED`، `ENROLLMENT_COMPLETED`، `ENROLLMENT_WITHDRAWN`، `RE_ENROLLMENT` یا `INSTRUCTOR_CHANGED`. `ADMIN_CORRECTION` فقط برای اصلاح مدیریتی مستند است.
- برای بستن کلاس، ابتدا enrollmentهای فعال را تکمیل/پس‌گرفته و assignmentهای فعال را لغو کنید.
- برای آرشیو دوره، همه کلاس‌ها باید نهایی `CLOSED` باشند. `ARCHIVED` و `CLOSED` مسیر بازگشت ندارند.
- تاریخچه را از `/admin/lms/lifecycle/` با نوع و UUID داخلی منبع بخوانید. permission منبع در هر درخواست تازه کنترل می‌شود و خروجی نباید به ticket یا گزارش حاوی PII کپی شود.

## پاسخ رخداد

- برای قطع فوری دسترسی دانشجو، enrollment را `WITHDRAWN` یا کلاس را `CLOSED` کنید.
- برای قطع دسترسی مدرس، assignment را revoke کنید.
- برای توقف انتشار همه کلاس‌های یک دوره، دوره را `DRAFT` یا `ARCHIVED` کنید.
- برای یافتن رکوردهای قدیمی از صفحه‌بندی مستقل دوره، کلاس، assignment و enrollment استفاده کنید؛ سقف ثابتی که رکورد فعال را غیرقابل‌دسترسی کند وجود ندارد.
- عنوان یا متن درس، ایمیل و PII را در audit یا گزارش رخداد کپی نکنید؛ فقط UUID داخلی، action code و request ID را ثبت کنید.
- جدول `lms_lifecycle_events` append-only است؛ اصلاح رخداد قبلی ممنوع و اصلاح منطقی فقط با رخداد جدید `ADMIN_CORRECTION` انجام می‌شود.

## rollback ۳C.۴

۳C.۴ migration یا تغییر schema ندارد؛ در صورت نیاز می‌توان کد و UI این فاز را به نسخه ۳C.۳ بازگرداند، بدون اینکه migrationهای `0000` تا `0004` تغییر کنند. عنوان‌ها یا جایگاه‌هایی که پیش‌تر با PATCH موفق در D1 ثبت شده‌اند با rollback کد خودکار بازگردانده نمی‌شوند؛ اصلاح آن‌ها باید آگاهانه و با نسخه جاری انجام شود. پس از هر rollback نیز writer باید با schema موجود و revision flow فاز ۳C.۳ سازگار بماند.

## rollback ۳C.۲

migration `0003` را down یا حذف نکنید. در رخداد بحرانی، mutationهای LMS را متوقف کنید، snapshot D1 بگیرید و نسخه سازگار اصلاحی deploy کنید. rollback کد به writer قدیمی ۳C.۱ می‌تواند optimistic lock و تاریخچه را دور بزند و مجاز نیست؛ read-only کردن پنل امن‌ترین توقف موقت است.

## rollback ۳C.۳

اگر `0004` هنوز اعمال نشده است، کامیت ۳C.۳ قابل revert است. پس از اعمال migration، جدول‌ها و pointer حذف یا بازنویسی نمی‌شوند و writer قدیمی ۳C.۲ نباید deploy شود. mutation محتوای درس را متوقف، پنل را موقتاً read-only و نسخه اصلاحی سازگار با schema را به‌صورت fix-forward منتشر کنید.
