# مدل تهدید حساب‌ها — فاز ۳A

> وضعیت: تحلیل پیش از پیاده‌سازی. این سند جایگزین آزمون نفوذ، بازبینی حقوقی یا برنامه پاسخ رخداد نیست.

## دارایی‌های محافظت‌شونده

- هویت و راه ارتباطی کاربران؛
- اطلاعات آموزشی، تحویل تمرین، نمره و بازخورد مدرس؛
- پیوند والد یا سرپرست با دانش‌آموز زیر ۱۸ سال؛
- متن و وضعیت رضایت؛
- نقش‌ها، نشست‌ها و مجوزهای سازمانی؛
- رویدادهای حسابرسی و نسخه‌های پشتیبان.

## مهاجمان و خطاهای محتمل

- فرد بیرونی با اطلاعات ورود سرقت‌شده؛
- کاربر معتبر که شناسه منبع فرد دیگری را تغییر می‌دهد؛
- والد یا فردی که بدون اختیار، درخواست اتصال به پرونده کودک می‌دهد؛
- مدرس یا مدیر با دسترسی بیش از نیاز؛
- اسکریپت خودکار برای حدس رمز، بازیابی حساب یا استخراج داده؛
- خطای توسعه، پیکربندی یا پشتیبان‌گیری که داده را افشا می‌کند.

## سناریوی ویژه افراد زیر ۱۸ سال

1. صفحه عمومی نباید فرم مستقلی برای کودک ارائه کند.
2. ایجاد پرونده از حساب والد یا سرپرست آغاز می‌شود.
3. تا پیش از تأیید پیوند و رضایت، داده آموزشی کودک قابل مشاهده نیست.
4. اطلاعات پزشکی، مدارک هویتی، نشانی دقیق یا داده تبلیغاتی کودک جزو مدل پایه نیست.
5. دسترسی والد، مدرس و مدیر هرکدام شرط جدا دارد و قابل جمع‌کردن ضمنی نیست.
6. درخواست اصلاح، حذف یا قطع پیوند باید مسیر عملیاتی و زمان پاسخ مصوب داشته باشد.

## حریم خصوصی صفحه پیش‌نمایش ۳A

صفحه `/account/` فقط HTML و CSS است و از اسکریپت مشترک منو استفاده می‌کند. این صفحه:

- فرم، فیلد ورودی یا ارسال شبکه ندارد؛
- از `localStorage` یا `sessionStorage` استفاده نمی‌کند؛
- حساب، رمز، اطلاعات کودک یا رویداد فعالیت ایجاد نمی‌کند؛
- فعال‌بودن ثبت‌نام یا ورود را ادعا نمی‌کند.

اسکریپت `scripts/validate-phase3.mjs` این محدودیت‌ها را در کنترل خودکار بررسی می‌کند.

- مدت نگهداری انواع داده و محل میزبانی مشخص نیست.
- ارائه‌دهنده هویت و مدل بازیابی انتخاب نشده است.
- مسئول پاسخ رخداد، کانال گزارش و زمان‌بندی اطلاع‌رسانی تعیین نشده است.
- سیاست دسترسی پشتیبانی و بازبینی دوره‌ای نقش‌ها نیازمند مالک سازمانی است.

تا بسته‌شدن این موارد، ورود و ذخیره داده واقعی نباید فعال شود.
